# Day 07 - Linux File System Hierarchy & Scenario-Based Practice

## Linux File System Hierarchy

Understanding the Linux file system is important because it helps locate configuration files, logs, user data, and executable programs while troubleshooting Linux systems.

---

### 1. Root Directory (`/`)

**Purpose:**

The root directory is the top level of the Linux file system. Every other file and directory starts from here.

**Command**

```bash
ls -l /
```

**Observed Directories**

- etc
- home

**When would I use it?**

Whenever I need to navigate through the Linux file system or locate important system directories.

---

### 2. Home Directory (`/home`)

**Purpose:**

Stores personal files and folders for regular users.

**Command**

```bash
ls -l /home
```

**Observed**

- ubuntu

**When would I use it?**

To access my files, scripts, or project directories.

---

### 3. Root User Directory (`/root`)

**Purpose:**

This is the home directory for the root (administrator) user.

**Command**

```bash
sudo ls -la /root
```

**Observed**

- .bashrc
- .profile

**When would I use it?**

When performing administrative tasks as the root user.

---

### 4. Configuration Directory (`/etc`)

**Purpose:**

Contains configuration files for the operating system and installed services.

**Command**

```bash
ls -l /etc
cat /etc/hostname
```

**Observed**

- hostname
- hosts

**When would I use it?**

While modifying system settings or troubleshooting application configurations.

---

### 5. Log Directory (`/var/log`)

**Purpose:**

Stores log files generated by Linux and running services.

**Command**

```bash
ls -lh /var/log
du -sh /var/log/* 2>/dev/null | sort -h | tail -5
```

**Observed**

- journal
- auth.log

**When would I use it?**

To investigate system errors, service failures, or login activity.

---

### 6. Temporary Directory (`/tmp`)

**Purpose:**

Used for temporary files created by users and applications.

**Command**

```bash
ls -la /tmp
```

**Observed**

- Temporary files created during testing

**When would I use it?**

While testing scripts or storing temporary data.

---

### 7. Binary Directory (`/bin`)

**Purpose:**

Contains essential Linux commands required for normal system operation.

**Command**

```bash
ls /bin | head
```

**Observed**

- ls
- cp

**When would I use it?**

When running basic Linux commands.

---

### 8. User Binary Directory (`/usr/bin`)

**Purpose:**

Stores most of the executable programs installed on the system.

**Command**

```bash
ls /usr/bin | head
```

**Observed**

- awk
- grep

**When would I use it?**

Whenever executing installed applications or utilities.

---

### 9. Optional Software Directory (`/opt`)

**Purpose:**

Used for installing third-party applications.

**Command**

```bash
ls -l /opt
```

**Observed**

- Directory was empty.

**When would I use it?**

When installing software that isn't included with the operating system.

---

# Scenario-Based Practice

## Scenario 1: Service Not Starting

### Step 1

```bash
systemctl status myapp
```

**Reason**

Check whether the service is running, stopped, or has failed.

---

### Step 2

```bash
systemctl list-units --type=service
```

**Reason**

Verify whether the service exists on the system.

---

### Step 3

```bash
systemctl is-enabled myapp
```

**Reason**

Determine if the service is configured to start automatically during boot.

---

### Step 4

```bash
journalctl -u myapp -n 50
```

**Reason**

Review recent log entries to identify startup errors.

**Observation**

The service was not available on my system, so no logs were found.

---

# Scenario 2: High CPU Usage

### Step 1

```bash
top
```

**Reason**

Monitor CPU usage in real time and identify resource-intensive processes.

---

### Step 2

```bash
ps aux --sort=-%cpu | head -10
```

**Reason**

Display the top processes consuming CPU resources.

---

### Step 3

Record the PID of the process using the highest CPU.

**Reason**

The PID helps identify or terminate a problematic process if necessary.

---

# Scenario 3: Finding Service Logs

### Step 1

```bash
systemctl status ssh
```

**Reason**

Confirm that the SSH service is active.

---

### Step 2

```bash
journalctl -u ssh -n 50
```

**Reason**

View the latest log entries related to the SSH service.

---

### Step 3

```bash
journalctl -u ssh -f
```

**Reason**

Monitor SSH logs in real time while troubleshooting.

---

# Scenario 4: Permission Denied

### Step 1

```bash
ls -l backup.sh
```

**Reason**

Check the current file permissions.

---

### Step 2

```bash
chmod +x backup.sh
```

**Reason**

Grant execute permission to the script.

---

### Step 3

```bash
ls -l backup.sh
```

**Reason**

Verify that execute permission has been added successfully.

---

### Step 4

```bash
./backup.sh
```

**Reason**

Run the script to confirm that the permission issue has been resolved.

---
